# Architecture — ResumeIQ

## Overview

ResumeIQ is a full-stack TypeScript monorepo built with pnpm workspaces. The system separates concerns into two runnable artifacts (frontend + backend) and four shared libraries. The API contract is defined once in an OpenAPI 3.1 spec and code-generated into type-safe React Query hooks and Zod validators.

---

## System Diagram

```
Browser
  │
  ├── GET /                     → Vite Dev Server (resume-analyzer artifact)
  │     React SPA (wouter routing)
  │     │
  │     ├── useAuth()           → @workspace/replit-auth-web
  │     ├── useListAnalyses()   → @workspace/api-client-react (generated)
  │     ├── useCreateAnalysis() → @workspace/api-client-react (generated)
  │     └── pdfjs-dist          → Client-side PDF extraction
  │
  └── /api/*                    → Express API Server (api-server artifact)
        │
        ├── authMiddleware      → Reads session cookie → loads user
        ├── /auth/*             → OIDC login/callback/logout (openid-client)
        ├── /analyses           → CRUD + stats
        │     └── resumeAnalyzer.ts → OpenAI GPT-4o (structured JSON)
        └── PostgreSQL          → Drizzle ORM (users, sessions, analyses)
```

## Monorepo Packages

### `artifacts/resume-analyzer` (web)
The React + Vite SPA. All routing is client-side via wouter. Communicates with the API server through relative `/api/` URLs (no hardcoded hosts). Generated hooks from `@workspace/api-client-react` manage all data fetching and caching.

### `artifacts/api-server` (API)
Node.js + Express server. Compiled with esbuild via a custom `build.mjs` script. All routes are mounted under `/api/`. CORS is configured with `credentials: true` and `origin: true` for the proxied Replit dev environment.

### `lib/api-spec`
Single source of truth: `openapi.yaml` (OpenAPI 3.1). Running `pnpm --filter @workspace/api-spec run codegen` triggers Orval v8 to generate:
- `lib/api-client-react/src/generated/` — React Query hooks with a custom `customFetch` mutator
- `lib/api-zod/src/generated/` — Zod v4 validators for request/response validation

### `lib/db`
Drizzle ORM schema and client. Three tables:
- `users` — Replit Auth user profiles
- `sessions` — OIDC session store (SID → JSON blob + expiry)
- `analyses` — All resume analysis results (JSONB columns for structured AI output)

### `lib/api-client-react`
Generated by Orval. Exports typed async functions and React Query hooks. Uses a `customFetch` mutator that automatically prefixes `/api` and attaches credentials. Do not edit manually — regenerate via codegen.

### `lib/replit-auth-web`
Thin browser auth package. Exports `useAuth()` which polls `/api/auth/user` and provides `{ user, isAuthenticated, isLoading, login, logout }`. `login()` navigates to `/api/login`, `logout()` navigates to `/api/logout`.

## Data Flow: Resume Analysis

```
1. User uploads PDF → pdfjs-dist extracts text client-side
2. User pastes job description
3. POST /api/analyses { resumeText, jobDescription, fileName }
4. authMiddleware validates session cookie → req.user populated
5. resumeAnalyzer.ts builds GPT-4o prompt (structured JSON mode)
6. GPT-4o returns: { atsScore, matchedSkills, missingSkills, weakPoints,
                     suggestions, scoreBreakdown, resumeStrengths,
                     jobTitleGuess, overallSummary }
7. Result inserted into analyses table (JSONB columns)
8. 201 response with full Analysis object
9. Frontend invalidates listAnalyses + getUserStats query caches
10. User redirected to /results/:id
```

## Authentication Flow

ResumeIQ uses Replit Auth (OIDC/PKCE):

```
1. User clicks "Sign In" → login() → GET /api/login
2. Server generates PKCE code_verifier + code_challenge
3. Redirect to Replit OIDC authorization endpoint
4. Replit redirects back to GET /api/callback?code=...&state=...
5. Server exchanges code for tokens via openid-client
6. Claims extracted → user upserted into `users` table
7. Session created in `sessions` table (SID = 32-byte random hex)
8. SID set as HttpOnly secure cookie (`sid`)
9. authMiddleware reads SID on every request → populates req.user
```

## API Contract (Code Generation)

The OpenAPI spec in `lib/api-spec/openapi.yaml` is the contract boundary. Orval v8 generates:

- **React Query hooks** with typed parameters, return types, and error types
- **Zod schemas** for runtime validation of API inputs/outputs

After any spec change:
```bash
pnpm --filter @workspace/api-spec run codegen
```

The codegen script runs Orval and then `tsc --build` to verify the generated code compiles. If it fails, the spec change is invalid.

## Database Schema

### `users`
```sql
id              VARCHAR PRIMARY KEY  -- Replit user sub claim
email           VARCHAR UNIQUE
first_name      VARCHAR
last_name       VARCHAR
profile_image_url VARCHAR
created_at      TIMESTAMP WITH TZ
updated_at      TIMESTAMP WITH TZ
```

### `sessions`
```sql
sid             VARCHAR PRIMARY KEY  -- Random 32-byte hex
sess            JSONB                -- { user, access_token, expires_at }
expire          TIMESTAMP            -- Session expiry
```

### `analyses`
```sql
id              SERIAL PRIMARY KEY
user_id         VARCHAR REFERENCES users(id)
ats_score       INTEGER              -- 0–100
job_title_guess VARCHAR
file_name       VARCHAR
job_description TEXT
resume_text     TEXT
score_breakdown JSONB                -- { keywordMatch, formatScore, ... }
matched_skills  JSONB                -- SkillItem[]
missing_skills  JSONB                -- SkillItem[]
weak_points     JSONB                -- WeakPoint[]
suggestions     JSONB                -- Suggestion[]
resume_strengths JSONB               -- string[]
overall_summary TEXT
created_at      TIMESTAMP WITH TZ
```

## AI Prompt Engineering

`resumeAnalyzer.ts` sends a single user message to GPT-4o with:
1. The full resume text
2. The full job description
3. A detailed JSON schema for the expected output
4. Instructions for calibrating ATS scores (keyword density, format penalties, experience gaps)
5. `response_format: { type: "json_object" }` for structured output

The prompt is designed to produce consistent, normalized scores — not just keyword frequency matching but also format quality, quantifiable achievement detection, and section structure analysis.

## Key Design Decisions

| Decision | Rationale |
|---|---|
| OpenAPI-first codegen | Single source of truth; eliminates drift between client types and server |
| Client-side PDF extraction | Avoids file upload infrastructure; reduces server load; keeps resume data private |
| JSONB columns for AI output | Flexible schema for evolving AI response shapes; queryable with Postgres JSON operators |
| Orval over tRPC | Better OpenAPI alignment; works with any HTTP client; REST is more universally understood in interviews |
| Zod v4 via `lib/api-zod` | Runtime validation of all API inputs; generated from same spec as TypeScript types |
| No file storage | Text extraction happens client-side; only extracted text is sent to the server |
| Session-based auth (not JWT) | Server-side sessions allow instant revocation; simpler than refresh token rotation |
