---
name: Orval v8 + Zod v3 compatibility
description: How to avoid Zod v4-only APIs being generated by Orval v8 when the workspace uses zod@3.25.76
---

Orval v8 generates Zod v4 syntax from certain OpenAPI annotations:
- `format: email` → `z.email()` (v4 only)
- `format: uri` → `z.url()` (v4 only)
- `type: integer` → `z.int()` (v4 only)

`zod@3.25.76` ships both v3 and v4 APIs, but `import from 'zod'` resolves to the v3 namespace (no `z.int`, `z.email`, `z.url`).

**Fix:** In the OpenAPI spec, remove `format: email`, `format: uri`, and use `type: number` instead of `type: integer`. This makes Orval emit `z.string()` and `z.number()` which exist in both versions.

**Why:** tsconfig `paths` aliases don't reliably override pnpm virtual store resolution for composite libs with declaration emit. Fixing the spec is safer than trying to remap the module.

**How to apply:** Any time you write an OpenAPI spec in this workspace and then run codegen, avoid those three constructs. Check generated api.ts for `.int(`, `.email(`, `.url(` — if present, the spec needs adjustment.
